Laboratorio Práctico

LAB: FILE PATH TRAVERSAL TRAVERSAL SEQUENCES BLOCKED WITH ABSOLUTE PATH BYPASS

Informe técnico sobre la explotación de la vulnerabilidad de salto de directorio mediante el bypass de secuencias relativas bloqueadas utilizando rutas absolutas para leer el archivo sensible /etc/passwd.

01

Ficha del laboratorio

Laboratorio: LAB: FILE PATH TRAVERSAL TRAVERSAL SEQUENCES BLOCKED WITH ABSOLUTE PATH BYPASS
Nivel: Apprentice
Tipo de explotación: File Path Traversal con bypass de rutas absolutas

02

Objetivo del laboratorio

Explotar la vulnerabilidad de salto de directorio para leer el contenido del archivo sensible /etc/passwd en el servidor backend.

03

Explicación técnica de la vulnerabilidad

La causa raíz de esta vulnerabilidad radica en que la aplicación web procesa de manera insegura la entrada provista por el usuario para interactuar directamente con la API del sistema de archivos mediante funciones subyacentes del backend. Específicamente, aunque los desarrolladores intentaron mitigar ataques de recorrido de directorios bloqueando o sanitizando secuencias relativas (como ../), el mecanismo de validación es insuficiente. Al recibir una ruta absoluta que comienza desde la raíz del sistema operativo (por ejemplo, /etc/passwd), la aplicación omite la concatenación con el directorio base previsto y procede a abrir directamente el archivo solicitado. Esto ocurre porque el motor del sistema operativo interpreta la barra diagonal inicial como el directorio raíz, permitiendo el acceso indebido.

En cuanto al marco CIA, esta vulnerabilidad compromete gravemente la Confidencialidad al permitir la lectura de información confidencial del sistema operativo y de los usuarios registrados. Desde la perspectiva de OWASP Top 10, se clasifica en A01:2021-Broken Access Control.

Su impacto y riesgo real en un entorno de producción incluyen la exposición de credenciales, información de configuración del sistema y archivos de código fuente, facilitando ataques subsecuentes de mayor criticidad.

04

Procedimiento paso a paso

  • El laboratorio se abordó utilizando un enfoque metodológico estructurado con el apoyo de Burp Suite como proxy de intercepción. En primer lugar, se configuró el navegador integrado para enrutar el tráfico web y verificar el funcionamiento general de la tienda en línea.
  • Durante la navegación por el catálogo de productos, se observó que las imágenes se cargaban mediante solicitudes HTTP que incluían el parámetro filename, el cual apunta a un directorio de imágenes específico en el servidor backend.
  • Para analizar el comportamiento de la aplicación ante entradas maliciosas, una de las peticiones de imágenes fue interceptada y reenviada a la herramienta Repeater.
  • Inicialmente, se intentó aplicar un ataque clásico de Path Traversal utilizando secuencias relativas de puntos y barras diagonales (../../../etc/passwd), las cuales fueron bloqueadas por el sistema de defensa de la aplicación, devolviendo un código de error HTTP 400 y el mensaje 'No such file'.
  • Dado que las secuencias relativas estaban bloqueadas, se procedió a evaluar si el backend implementaba un bypass mediante rutas absolutas. Se modificó el parámetro filename para apuntar directamente a la ruta raíz del sistema utilizando /etc/passwd sin incluir secuencias de navegación previa.
  • Al enviar esta petición modificada a través del Repeater, el servidor procesó la ruta absoluta sin restricciones, devolviendo un código de estado HTTP 200 OK y el contenido completo del archivo /etc/passwd en la respuesta.
  • Finalmente, al actualizar la interfaz web principal, se confirmó la resolución exitosa del laboratorio mediante la notificación de 'Lab Solved'.

07

Explicación del payload

El payload utilizado en este laboratorio consiste en una ruta absoluta directamente apuntando al archivo sensible del sistema operativo: /etc/passwd.

A diferencia de los payloads tradicionales de Path Traversal que utilizan secuencias relativas (../) para retroceder niveles en la jerarquía de directorios, este enfoque omite por completo el uso de puntos y barras de navegación. El parámetro afectado es filename, el cual es procesado por el backend web.

El mecanismo de evasión se fundamenta en la debilidad de la lógica de validación del desarrollador, quien únicamente diseñó defensas contra el incremento de directorios relativos pero omitió restringir el uso de rutas que inician desde la raíz del sistema (/). Al recibir esta entrada, el sistema de archivos del servidor interpreta el slash inicial como el directorio raíz absoluto, ignorando cualquier carpeta de trabajo predeterminada y abriendo directamente el archivo solicitado para retornar su contenido en la respuesta HTTP.

08

Mitigación recomendada

Para mitigar eficazmente las vulnerabilidades de File Path Traversal y el bypass de rutas absolutas, es fundamental implementar una estrategia de defensa en profundidad:

  • 1. Evitar paso directo de entradas: Como primera medida de remediación en el código, se debe evitar en la medida de lo posible pasar entradas directamente proporcionadas por el usuario a APIs del sistema de archivos.
  • 2. Validación por lista blanca (Whitelisting): Si es estrictamente necesario, se debe implementar una validación estricta utilizando listas blancas de nombres de archivos permitidos o verificar que la entrada contenga exclusivamente caracteres alfanuméricos seguros.
  • 3. Canonicalización de rutas: Adicionalmente, se debe emplear la funcionalidad de canonicalización de rutas provista por el lenguaje de programación (por ejemplo, el método getCanonicalPath() en Java), asegurando que la ruta resultante comience exactamente dentro del directorio base autorizado.
  • 4. Principio de menor privilegio: A nivel de arquitectura y red, se recomienda aplicar el principio de menor privilegio sobre los permisos de lectura del usuario con el que se ejecuta el servidor web, restringiendo el acceso a archivos del sistema operativo como /etc/passwd.
  • 5. Implementación de WAF: Finalmente, es recomendable el uso de un Web Application Firewall (WAF) debidamente configurado para inspeccionar y bloquear patrones maliciosos de recorrido de directorios y rutas absolutas no autorizadas.
